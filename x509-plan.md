# x509: plan

Item 4 of `missing-libraries.md`. Scope agreed 2026-11-19: parse, verify,
the TLS peer's chain (mTLS client identity), and CSRs and self-signed
certificates. Those are what ACME (Let's Encrypt) needs; ACME itself is a
later package.

## Shape

- **`stdlib/x509`**, a source package with `Cert` and the functions below.
  It is in the batteries and linked only when imported.
- **OpenSSL does the ASN.1.** DER parsing is where certificate libraries
  get their CVEs. OpenSSL is already linked for `crypto` and `net` TLS, so
  this adds no dependency.
- **Natives are `crypto.x509_*`.** A native returns scalars, bytes and
  `[str]`, never a struct, so the source package builds `Cert` from them.
  They run in `runtime/sl_x509.c`, which is compiled in only when a program
  calls one of them (`want_x509`, set the way `want_tls` is). Programs that
  use `crypto` without X.509 do not compile it.
- **Stack and init:** every native starts with `SL_CRYPTO_STACK()` and
  runs the one-time OpenSSL fetch before decoding (#553), inside the
  preempt bracket.

## API

```slang
pub struct Cert {
    der: bytes,            // exactly the bytes that were parsed
    subject: str,          // RFC 4514: "CN=api.example.com,O=Example"
    common_name: str,      // the subject's CN, "" if it has none
    issuer: str,
    serial: str,           // lowercase hex
    not_before: int,       // unix seconds
    not_after: int,
    dns_names: [str],      // subjectAltName, by type
    ip_addrs: [str],
    emails: [str],
    uris: [str],
    is_ca: bool,
    max_path_len: int,     // -1 when absent
    key_usage: [str],      // "digital_signature", "key_encipherment", "cert_sign", ...
    ext_key_usage: [str],  // "server_auth", "client_auth", ...; others as dotted OIDs
    key_type: str,         // "rsa", "ec-p256", "ec-p384", "ed25519", ...
    key_bits: int,
    public_key_pem: str,   // SPKI PEM, which crypto's *_from_pem and verify functions take
    signature_alg: str,    // "sha256WithRSAEncryption", "ecdsa-with-SHA256", ...
    fingerprint: str,      // SHA-256 of der, lowercase hex
}

pub fn parse_pem(pem: str) -> result[[Cert], str]    // every CERTIFICATE block, in order
pub fn parse_der(der: bytes) -> result[[Cert], str]  // one certificate or several concatenated
pub fn matches_host(c: Cert, host: str) -> bool      // RFC 6125 via OpenSSL: SANs only, never CN
pub fn valid_at(c: Cert, unix: int) -> bool

pub struct Verify {
    roots_pem: str,        // "": the system roots
    host: str,             // "": no hostname check
    at: int,               // 0: now
    purpose: str,          // "server", "client" or "": no purpose check
}
pub fn verify(chain: [Cert], v: Verify) -> result[bool, str]   // chain[0] is the leaf

pub struct Request {
    common_name: str,
    dns_names: [str],
    ip_addrs: [str],
}
pub fn csr(key_pem: str, r: Request) -> result[str, str]               // PKCS#10, PEM
pub fn self_signed(key_pem: str, r: Request, days: int) -> result[str, str]
```

`verify` returns its own fixed reasons for the common failures
("certificate has expired", "certificate signed by unknown authority",
"hostname mismatch", ...), because OpenSSL rewords its strings between
versions; rarer failures carry OpenSSL's text.

## Natives

| native | returns |
|---|---|
| `crypto.x509_der(pem: str)` | `result[bytes,str]`: every CERTIFICATE block as concatenated DER |
| `crypto.x509_fields(der: bytes)` | `result[[str],str]`: the first certificate's fields in a fixed order, led by its DER length |
| `crypto.x509_check_host(der: bytes, host: str)` | `bool` |
| `crypto.x509_verify(chain: bytes, roots_pem: str, host: str, at: i64, purpose: str)` | `result[bool,str]` |
| `crypto.x509_csr(key_pem: str, cn: str, sans: [str])` | `result[str,str]` |
| `crypto.x509_self_signed(key_pem: str, cn: str, sans: [str], days: i64)` | `result[str,str]` |
| `crypto.ecdsa_p256_private_to_pem(key: bytes)` | `result[str,str]` |
| `crypto.ed25519_private_to_pem(seed: bytes)` | `result[str,str]` |
| `net.tls_peer_certs(conn: rawptr)` | `bytes`: the peer's chain as concatenated DER, leaf first |
| `link.peer_certs()` | the same, on a link after `c.tls_accept` |

The peer's chain is read with `x509.parse_der(c.peer_certs())` or
`x509.parse_der(net.tls_peer_certs(ssl))`. x509 does not import `net`, so a
program that only reads certificates does not link TLS or the reactor.

The two `*_private_to_pem` functions exist because `ecdsa_p256_generate`
and `ed25519_generate` return raw keys, and a CSR, a self-signed
certificate and `net.tls_ctx_use_cert` all take PEM. `rsa_generate`
already returns PEM.

## Tests

- **`tests/x509`:** parse a fixed chain (generated by `gen.py` with
  `openssl`, then committed) and check every field. Also: verify against
  its root, then the failure paths (expired, wrong host, unknown issuer,
  wrong purpose).
- **`tests/x509_make`:** a CSR and a self-signed certificate from P-256,
  Ed25519 and RSA keys, read back with `parse_pem`. The self-signed one
  must verify against itself.
- **`tests/x509_peer`:** mTLS against a local listener; the server reads
  the client's chain with `link.peer_certs()` and `net.tls_peer_certs`.
- **`tests/fail_x509_*`:** argument types.
- **`stdlib/x509/x509_test.sl`:** the slang-side assembly.
