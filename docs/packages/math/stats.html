math/stats

Package math/stats.

Markdown·llms.txt·api.json

Statistics over lists of any numeric type, and streaming accumulators for numbers that never all exist at once. Written in slang over math.

slang
import "math/stats";

let xs = [12.5, 9.0, 14.25, 11.0];
stats.mean(xs);                      // 11.6875
stats.median(xs);                    // 11.75
stats.stddev(xs);                    // sample (n - 1); pstddev is population
stats.quantile(xs, 0.9);             // R type 7 / NumPy's default
stats.correlation(xs, ys);           // Pearson's r; spearman for ranks
let fit = stats.linear_regression(xs, ys);   // fit.slope, fit.intercept, fit.r2, fit.at(x)
let h = stats.histogram(xs, 10);     // h.edges, h.counts

// Streaming, O(1) per value, mergeable across tasks:
let lat = stats.running();           // count, mean, variance, min, max
lat.add(elapsed_ms);
let p = stats.digest();              // quantiles of a stream (t-digest)
p.add(elapsed_ms);
p.quantile(0.99);

stats.normal(100.0, 15.0).cdf(130.0);        // 0.9772498680518208
stats.normal(0.0, 1.0).quantile(0.975);      // 1.9599639845400538
stats.poisson(3.0).pmf(5);
stats.poisson(3.0).sample(rand.new(42));     // an int, replayable
  • Center and spread: sum (compensated), product, mean, weighted_mean, geometric_mean, harmonic_mean, median, mode, min, max, spread, variance/pvariance, stddev/pstddev, mad, zscores, skewness, kurtosis (excess).
  • Order: quantile, percentile, quartiles, iqr, ranks; sorted_floats and quantile_sorted to sort once and ask many times.
  • Two lists: covariance, correlation, spearman, linear_regression.
  • Streaming: running() (Welford), ewma(alpha) and ewma_half_life(n), digest() (a merging t-digest: p99 and p999 stay accurate in about 100 centroids). Each has add, and running and digest merge.
  • Distributions: normal, log_normal, uniform, exponential (pdf, cdf, quantile), poisson and binomial (pmf, cdf). Each has sample(r) for a rand.Rng, so a simulation or load generator replays from one seed: the ziggurat for the normal and the exponential, Hörmann's PTRS and BTRS (what numpy and TensorFlow use) for the Poisson and binomial once the mean reaches 10, multiplication or inversion below. All exact, all O(1) on average.

For experiments, math/stats has the tests and planning numbers an A/B test needs, and the distributions they rest on:

slang
let t = stats.two_proportion_z(120, 2400, 156, 2380);   // TestResult
t.p_value < 0.05;                                       // B beats A at 5%
stats.wilson(156, 2380, 0.95);                          // Interval { lo, hi }
stats.sample_size_proportions(0.05, 0.06, 0.05, 0.8);   // 8158 per arm
let s = stats.sprt(0.05, 0.06, 0.05, 0.2);
s.add(converted);                    // Decision.Continue until it can stop
  • Tests (two-sided p-values): two_proportion_z, welch_t (unequal variances), t_test (one sample), chi_square_test (an r x c table of counts), chi_square_fit.
  • Intervals and planning: wilson (stays in [0, 1], sane at 0 or n successes), mean_interval, sample_size_proportions, power_proportions, sample_size_means.
  • Sequential: sprt(p0, p1, alpha, beta), Wald's test: add or add_n outcomes and stop at Decision.AcceptNull or AcceptAlternative. Peeking is part of its design, so stopping early does not inflate the error rates.
  • Distributions: student_t(df) and chi_squared(k) (pdf, cdf, quantile to full precision), and the regularized incomplete beta and gamma functions under them, inc_beta and inc_gamma.

A result with no value for its input -- the mean of no numbers, the variance of one, a correlation with a constant list -- is NaN, which propagates and tests true with math.is_nan; functions that return one of the elements (min, max, mode) return an opt of the element type. Sums are compensated (Neumaier) and variances are two-pass around the mean, so neither drifts on long or offset data: stats.sum([0.1, 0.2, 0.3]) is 0.6.

fn sum[T](xs: [T]) -> float stdlib/math/stats/stats.sl:51#

The sum of xs, compensated: the exact rounding error of each addition (Knuth's TwoSum) is carried and added back at the end. 0 for an empty list; an infinity or NaN in xs gives the plain sum's inf or NaN. Two independent running sums take alternate elements, so consecutive additions do not wait on each other: one chain held a sum to the latency of a float add per element, about half the speed of a plain loop. Every list function here sums the same way, in place -- they used to collect the terms in a list first and sum that, which for variance on a million values made the pushes 90% of the time. A for x in xs loop, not a while over indices: the for loop takes its safepoint once around the loop and reads elements unchecked, where a while loop brackets every iteration and bounds-checks every index -- twice the time per element.
