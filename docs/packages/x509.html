x509

Package x509.

Markdown·llms.txt·api.json

X.509 certificates: read them, check them, and make requests for them.

slang
import "x509";

let r = x509.parse_pem(pem);              // result[[x509.Cert], str]: every CERTIFICATE block
guard let certs = r else let e = err_of(r) { panic(e); }
let c = certs[0];
c.common_name; c.dns_names; c.ip_addrs;   // the subject and its subjectAltName entries
c.not_after;                              // unix seconds
x509.expires_in(c);                       // seconds left; negative once expired
x509.matches_host(c, "www.example.com");  // RFC 6125, SANs only

let v = x509.Verify { roots_pem: "", host: "api.example.com", at: 0, purpose: "server" };
x509.verify(certs, v);                    // ok(true), or why not

let key = crypto.ecdsa_p256_private_to_pem(crypto.ecdsa_p256_generate() ?? b"") ?? "";
let names = x509.Request { common_name: "api.example.com",
                           dns_names: ["api.example.com"], ip_addrs: [] };
x509.csr(key, names);                     // result[str, str]: PKCS#10, PEM
x509.self_signed(key, names, 90);         // result[str, str]: a certificate, PEM

Cert holds der (exactly the bytes parsed), subject and issuer (RFC 4514, most specific first), common_name, serial (lowercase hex), not_before and not_after (unix seconds), dns_names, ip_addrs, emails and uris, is_ca and max_path_len (-1 when unset), key_usage (digital_signature, key_encipherment, cert_sign, ...), ext_key_usage (server_auth, client_auth, ...; others as dotted OIDs), key_type (rsa, ec-p256, ec-p384, ed25519, ...) and key_bits, public_key_pem (SPKI, which crypto's *_from_pem functions take), signature_alg and fingerprint (SHA-256 of der, lowercase hex). parse_der takes one certificate or several concatenated, as a TLS chain arrives.

Names. matches_host and verify's host follow RFC 6125: only subjectAltName entries count, never the subject CN (browsers and Go stopped trusting it); a wildcard is only the whole left-most label and stands for exactly one label; an IP literal matches IP entries, compared as addresses.

Verifying. chain[0] is the leaf, the rest intermediates in any order. roots_pem is the trust anchors ("" for the system's, loaded once and shared); at checks validity at a given time (0 for now); purpose is "server", "client" or "". A failure says why, in words that do not change with the OpenSSL version: certificate has expired, certificate is not yet valid, hostname mismatch, IP address mismatch, certificate is not for this purpose, certificate signed by unknown authority, self-signed certificate not in the roots, certificate signature does not verify, issuer is not a CA, path length constraint exceeded.

Client identity (mTLS). With net.tls_ctx_require_client the handshake has verified the client's chain; read it with x509.parse_der(c.peer_certs()) on a link, or x509.parse_der(net.tls_peer_certs(ssl)) on a handle from net.tls_accept. x509 does not import net, so a program that only reads certificates does not link TLS.

Making them. csr builds the PKCS#10 request an ACME server or any CA takes: the names, the public key, signed by the private key (RSA, EC or Ed25519 in PEM). self_signed makes a leaf for development TLS and tests: CA:FALSE, server and client auth, a random 128-bit serial, valid from now for 1 to 36500 days; verify it by passing its own PEM as the roots. Request needs a common name or at least one DNS name or IP.

All the ASN.1 is OpenSSL's; the package parses no DER itself. Errors start with x509: .

Does the certificate name host? RFC 6125: subjectAltName entries only, never the subject CN; a wildcard only as the whole left-most label, for exactly one label ("*.example.com" matches "a.example.com", not "example.com" or "a.b.example.com"). An IP literal matches IP entries.

fn verify(chain: [Cert], v: Verify) -> result[bool, str] stdlib/x509/x509.sl:189#

Checks chain (the leaf first, then any intermediates) up to one of the roots: every signature, validity at v.at, and the host and purpose when set. ok(true), or why not, in words that do not change with the OpenSSL version: "x509: certificate has expired", "x509: certificate is not yet valid", "x509: hostname mismatch", "x509: IP address mismatch", "x509: certificate is not for this purpose", "x509: certificate signed by unknown authority", "x509: self-signed certificate not in the roots", "x509: certificate signature does not verify", "x509: issuer is not a CA", "x509: path length constraint exceeded"; rarer failures carry OpenSSL's own reason.

fn csr(key_pem: str, r: Request) -> result[str, str] stdlib/x509/x509.sl:216#

A certificate signing request (PKCS#10, PEM) for r's names, signed with key_pem (an RSA, EC or Ed25519 private key in PEM). It is what an ACME server, or any CA, is sent: it carries the names and the public key, and proves the sender holds the private key.

fn self_signed(key_pem: str, r: Request, days: int) -> result[str, str] stdlib/x509/x509.sl:224#

A certificate for r's names, signed by its own key and valid from now for days (1 to 36500): for development TLS and tests. It is a leaf (not a CA) for server and client auth; to verify it, pass its own PEM as roots_pem.
