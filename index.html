Concurrency

Park the task, not the thread.

spawn puts a green task on a pool with one worker per core. Sockets, sleeps, channels and locks park the task and hand the thread back. There is no async, no await and no second colour of function: code that looks blocking stays simple.

  • 10,000 tasks that each sleep 100 ms finish in about 0.6 s on a laptop.
  • Preempted when a task spins past its slice, so one hot loop cannot starve a worker.
  • TLS and DNS park too. Handshakes run on the reactor; lookups on their own thread.
  • A precise, generational GC with a write barrier and a verifier mode in CI.

Cheap to learn. Cheap to correct.

An agent spends its tokens reading docs, choosing between options and retrying after errors. slang is designed to cut all three, for the agent and for whoever reviews its work.

Errors that say the fix

A compile error names the construct, the line and what to write instead. A runtime error names the function and the values, so the next attempt is the right one.

one turn to fix, not five
~/orders$ slangc main.sl
!main.sl:1: error: cannot infer the element type of an empty list; annotate it, e.g. let xs: [int] = []

~/orders$ ./orders
!slang runtime error: list index out of bounds at orders.line_total:2 (index 7, length 3)

zokor

One way to do each thing.

zokor is the backend framework for slang. It makes the decisions every service otherwise makes differently, so neither an agent nor a new hire has to.

routes.sl
r.get("/health", health);            // public

let api = r.group("/api/v1");
api.before(require_token);           // everything below is guarded
api.get("/orgs/:id", show_org);
api.post("/orgs", create_org);

fn show_org(c: zokor.Ctx[App]) -> http.Response {
    guard let org = find_org(c.state.db, c.param("id")) else {
        return zokor.respond(c.state.errors, "org.not_found", c.request_id);
    }
    return zokor.ok_json(encode(org));
}

Every choice an agent faces costs reasoning tokens. zokor answers them once.

The language

Familiar on purpose. Small on purpose.

Syntax you already read

fn, guard let, switch, chan: shapes from Go and Swift, because people and models already know them. Every novelty costs someone a retry.

fn abs(n: int) -> int {
    guard n >= 0 else {
        return -n;
    }
    n
}

let code = 404;
switch code {
  case 200, 201 { println("ok"); }
  case 404 { println("missing"); }
  default { println("other"); }
}

Left out, deliberately

Each missing feature is one less way for a program to surprise you.

No null
opt[T], unwrapped with guard let or ??
No exceptions
result[T, E] for bad data, fault for a bad world
No closures
A function value is a C function pointer. Nothing is captured
No interfaces, no reflection
Generics, checked for each type they are used with
No async, no await
spawn, and blocking calls that park

C is the runtime, not a foreign country

slang emits C and hands it to your cc. Calling a C library is extern fn and a linker flag: no bindings generator, no marshalling layer, no second build system.

link "sqlite3";

extern fn sqlite3_libversion() -> str;
println(sqlite3_libversion());

FAQ

Asked, answered.

Is slang ready for production?

It is young: v0.2, and the language can still change. The runtime is tested on three platforms on every merge, including a collector verifier and stress runs under forced preemption. Read Known limitations before you bet a service on it, and pin a commit when you do.

Is it faster than Go or Rust?

On what has been measured so far: it uses less memory than Go, finishes the CPU and allocation job in two thirds of Go's time, and trails Rust. Raw HTTP throughput is within a few percent of both. The heavier database-and-JSON tier has not run yet. The benchmarks page shows every number, including the ones slang loses.

Why compile to C?

C runs everywhere a server does, its compilers have decades of optimisation in them, and every C library is one extern fn away. slangc emits one C file with the runtime spliced in and builds it with cc -O3 -flto.

Why no closures, exceptions or null?

Each is a place where control flow or ownership hides. Without closures a function value is exactly a C function pointer and the collector can ignore it. Without exceptions every failure is a value you can see in the signature. Without null, absence is opt[T] and the compiler makes you handle it.

What does "cheap for agents" mean, and is it proven?

It means fewer tokens to learn the language, fewer choices to reason about, and errors that lead to the fix in one turn. It is a design goal, not a result yet: the agent benchmark above is built and published, and its first run is pending.

Can I call existing C libraries?

Yes: extern fn plus link "name". Numbers, bool, str, bytes and opaque pointers cross the boundary; GC-managed values are rejected at compile time, so C never sees their layout.

Who builds slang?
